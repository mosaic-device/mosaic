# Mosaic assets (phase 2)

Committed, self-hosted web fonts and LVGL 9 C assets. Normal web/IDF builds
consume these files: no network, Python, SVG renderer, or font converter runs.
Import `@mosaic/assets/fonts.css`; use `Manrope, system-ui, sans-serif` and
`Outfit, Manrope, system-ui, sans-serif`. No automatic preloads are prescribed.
`web/mosaic-wordmark.svg` is outlined, uppercase MOSAIC, Outfit 500, with
0.23em tracking between letters. There is no firmware Outfit runtime font.

## Layout

- `sources/`: pinned upstream inputs and static TTF intermediates; manifest paths are relative to this package root.
- `scripts/`: explicit maintenance generators and pinned Python requirements.
- `tests/`: offline validation of committed assets.
- `metadata/`: font coverage and output checksums (paths relative to this package root; no manifest self-hash).
- `licenses/` and `web/`: finished distribution notices and web assets.

Firmware outputs remain in `firmware/main/ui/generated/assets/` at the repository root.
Both generators resolve inputs and outputs from this package root regardless of invocation directory.

## Provenance

`sources/manifest.json` pins official upstream URLs, revisions and SHA-256 hashes.
Manrope 4.505 and Outfit 1.100 use SIL OFL; Lucide 0.468.0 uses ISC. Original
sources, notices, static TTF intermediates and converted outputs are committed.
`licenses/` contains the canonical distribution notices, copied from the sources.
Tests check source/output hashes, font attribution and embedded full OFL metadata,
recorded coverage, firmware declarations and distribution notices.

## Regenerate

Regeneration is explicit maintenance; normal `build` and `test` only validate
committed assets and do not run Python or converters. No sibling archive is needed.
From the repository root, install the pinned JS workspace dependencies with
`pnpm install --frozen-lockfile` (network or an existing pnpm cache is required).
Then create the isolated Python environment and install its pinned dependencies:

```sh
python3 -m venv platform/packages/assets/.venv
platform/packages/assets/.venv/bin/python -m pip install -r platform/packages/assets/scripts/requirements.txt
. platform/packages/assets/.venv/bin/activate
pnpm generate-assets
```

The active environment must put its `python3` on PATH. Environments are ignored;
Python installation may require network or a populated pip cache. Once dependencies
are installed, generation is offline. It verifies source checksums, regenerates
static TTF/WOFF2 fonts, then creates firmware C assets using firmware token sizes.
It refreshes canonical notices, firmware/admin notice copies, coverage and output
checksums. To rerun only the JS conversion using committed static TTF files:

```sh
pnpm --filter @mosaic/assets exec node scripts/generate.mjs
```

Generation overwrites converted assets; preserve intentional output edits first.
Run twice and compare `metadata/outputs.json` to check determinism. Review all output changes
and run `pnpm --filter @mosaic/assets test` and `pnpm --filter @mosaic/admin test`
(the latter builds and checks production). Commit sources/tooling and finished
assets together, but not environments or node_modules. Token output policy is
unchanged: token outputs are ignored and regenerated by consuming builds.

## Distribution notices

Generation copies the original Manrope OFL, Outfit OFL and Lucide license into
`firmware/main/ui/generated/assets/licenses/`, byte-for-byte. The generated
`README.md` explains which notice covers each asset and how to include notices
with source packages and firmware binary/device releases. Every generated font
C file retains upstream copyright and a full-license sidecar reference; masks
reference their applicable license too. These text files are not embedded in
the firmware image, so include them in release documentation/third-party notices.
`metadata/outputs.json` records sidecar checksums; tests compare them with the canonical in-repo notices.

## Firmware API and roles

`firmware/main/ui/generated/assets/assets.h` declares all symbols. The generated
`sources.cmake` explicitly enumerates C sources; main CMake includes it.
Manrope uses 4bpp uncompressed LVGL font data, at 28/32/36/48/60px and
400/500/600. The full 15-entry matrix avoids silently changing weight by size.
Use 28/400 captions, 32/400 supporting text, 36/400 body, 36/500 controls,
48/500 headings and 60/500 titles; reserve 600 for deliberate emphasis.
`GET_FONT(TOKEN_TEXT_*)` remains 400 and maps web token roles to device sizes.
`GET_FONT_WEIGHT(token, 500)` selects weight explicitly. Invalid weights fall
back to 400. Unknown roles fall back to 36px. Do not pass device pixel tokens
to the legacy role-dispatch API; use `ui_tokens_font_weight(pixels, weight)`.

Digit advances are normalized to the widest default digit in the static
Manrope outputs (web and firmware); no browser-only `tnum` assumption is made.
Glyph shapes are unchanged. This gives equal advances, not monospaced text.
Hardware clock strings/kerning still require gallery review.

## Coverage and fallback contract

Requested ranges: U+0020–017F (ASCII, Latin-1, Latin Extended-A),
U+2000–206F punctuation, U+20AC euro, U+2212 minus and U+FFFD.
`metadata/coverage.json` gives exact supported/missing codepoints per weight and digit
advances. All printable Latin-1, including degree U+00B0, is available. Extended-A
is **not complete in upstream Manrope**: U+0114/0115, 012C/012D, 0132/0133,
0138, 013F/0140, 0149, 014E/014F and 017F are absent. Not every punctuation
codepoint is supplied; curly quotes, en/em dash, bullet, ellipsis are supported.
Control characters are intentionally not rendered. U+FFFD itself is absent.

Dynamic input must be normalized to NFC and unsupported scalar values replaced
with ASCII `?` by the caller before display; retain original text in storage.
This package does not change existing runtime/input ownership. No arbitrary
Unicode promise, font fallback chain, CJK, emoji or shaping support is added.
Without caller sanitization, LVGL uses its missing-glyph behavior (not a promised
replacement character); web may use the explicit system fallback.

## Icons and wordmark

Included icon: `mosaic_icon_settings_40`, 40px firmware mask from the Lucide 24-unit SVG, stroke width 2.
Catalog: https://lucide.dev/icons/settings. To add another needed icon, choose
its source in the same versioned official repo, track SVG/license and checksum
in the manifest, add an explicit conversion and symbol, regenerate and review.
Do not download an entire catalog or render SVG at runtime.

Wordmarks: `mosaic_wordmark_40` and `mosaic_wordmark_60` are generated directly
from the outlined master at those ink heights, not enlarged from a raster.
Images are LVGL 9 A8 masks with explicit width/stride and no RGB data.
Use `lv_image_set_src`, set `image_recolor` to the desired color (off-white for
the wordmark), `image_recolor_opa` to `LV_OPA_COVER`, and `image_opa` for opacity.
Do not assume tint/opacity hardware review is complete.

## Footprint and validation boundary

`metadata/outputs.json` records C source and web bytes (C text is not flash usage).
See `metadata/outputs.json` for current WOFF2 sizes, including embedded license metadata. The 15 fonts have source byte sizes recorded in the manifest; C text is not flash usage.
Final linked flash depends on dead stripping and use. Built-in
Montserrat sdkconfig options remain untouched; remove unused options only after
checking all firmware references. Measure the firmware flash delta against an
IDF baseline and linked build. Validate text, missing-glyph handling, tint/opacity
and wordmark rendering in the on-device gallery before release.
